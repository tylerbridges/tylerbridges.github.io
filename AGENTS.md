# Repository workflow

Tyler's personal GitHub Pages weather site: a single-page, live weather.gov dashboard.
Optimize for a simple loop: request, implement, review, publish, verify.

## Publishing

- Work directly on `main` unless Tyler asks for a branch or pull request.
- Start with `git status`; when clean, `git pull --ff-only origin main`. Never discard pre-existing changes.
- Commit task-scoped files with a descriptive message and push with `git push origin main` without waiting for approval. Never force-push.
- After pushing, confirm `origin/main` has the commit and the GitHub Pages build finished, then load the live site and confirm it serves the change.
- Reply to a change with a bulleted list of what was done (including commit/deploy status). No "Couldn't do" or "Your action items" sections.

## How the site works

- `index.html` holds the markup and all CSS; `app.js` renders everything (Now, Daily, Hourly graphs, Maps with storm totals, Observations, location picker, refresh button); Radar and the Maps model viewer are their own files.
- Forecast tab (`data-tab="maps"`, `#forecast` also works; renamed from Maps since radar is the look-back view): top card "Official precipitation" (`renderOfficial()` in `app.js`, choice saved as `wx-oq2`): Precip / Snow / Ice × Next 24 hr / 48 hr, drawn by `wx-official.js` as a monochrome county map (white lines and numbers on black in dark mode, black on white in light; no colour fills, no colour key, no base-map tiles): thin county lines, state lines over them, and each county labelled with its amount at the county's label point (largest values first, overlaps skipped, so zoomed out only the biggest show; county lines hidden below zoom 4.6). Place names come from the OpenFreeMap tiles via `WXVMap.drawTop(…, { placesOnly, classes, avoid, text, halo })` (a dot with the name beside it, right side else left; no roads, boundaries or state names; returns the boxes it took): cities are placed first, then the county numbers (nudged a line down or up if a city is in the way), then towns in the gaps. Gear button bottom right (`.oqgear`) opens Map settings (`.oqset`, saved as `wx-oqset`): Cities & towns Show/Hide, County lines Show/Hide, Number size S/M/L (0.85/1/1.2×), Map colors Auto/Light/Dark (overrides the site theme for this map only), Dry counties Blank/Show 0 (grey "0" or "0%"); a tap on the map closes it. Pan, pinch, double-tap, Local/Region/U.S. (7.6/6.6/3.9, default 6.6); tap a county for its name, the WPC bands it spans and its average (e.g. "Hennepin, MN: .25–.75 in (avg .45)"); the product's own period top right; one caption line under the map says what the numbers are. Data: NOAA's ArcGIS services on `mapservices.weather.noaa.gov`, queried as JSON in lat/lon: `vector/rest/services/precip/wpc_qpf` layer 1 = 24-hour Day 1, layer 8 = 48-hour Days 1–2 (one multipolygon per contour level, field `qpf`; levels are exclusive bands with holes); `precip/wpc_prob_winter_precip` = chance of 4/8/12"+ snow (Day 1 layers 1/2/3, Day 2 layers 6/7/8) and 0.25"+ ice (Day 1 layer 4, Day 2 layer 9), field `outlook`; `static/rest/services/nws_reference_maps/nws_reference_map` layer 2 = counties (countyname, state, fips, lat/lon label point; loaded by 6°×4° cell at 0.008° detail from zoom 5.5, else all CONUS at 0.04°, paged past 2000 records), layer 3 = states. County values: the WPC polygons are rasterised onto a 0.04° grid and each county averages the cells inside it using band midpoints (top band = its floor); anything averaging under .10 reads "<.1" because WPC's lowest band is .01–.10, otherwise rounded to .05 (to .1 from 1 in). Snow/ice counties show the chance category covering at least a quarter of the county ("10%" = 10–39%, "40%", "70%"; blank under 10%). WPC publishes no official snow or ice amounts in a browser-readable form, so those tabs show chances, not inches. If the services fail, the card falls back to WPC's images (Precip `qpf/fill_94qwbg.gif` / `qpf/d12_fill.gif`, Snow `wwd/day{1,2}_psnow_gt_{04,08,12}_conus.gif`, Ice `wwd/day{1,2}_pice_gt_25_conus.gif`; WPC answers 403 to a "HeadlessChrome" user agent). Built in a sandbox that couldn't reach NOAA or Pivotal Weather: tested against saved real service replies served to headless Chromium. Under the map, this place's official rain/snow/ice for the next 24 or 48 hours from its weather.gov grid (`sumRange` on `doc.grid`; the selected kind is outlined). check.html reports whether the card drew ("official drawn …"). Below it the model viewer, `wx-models.js`, a Pivotal Weather–style model viewer that draws its own maps from raw NOAA model output (no images, no API). Built mainly for upcoming precipitation and snow: quick buttons above the map (`#mquick`: Precip type, Precip, Snow, Ice; everything else is in the dropdown), and every accumulation counts from now (`fromH()`: the last forecast hour at or before now; the product is total(h) − total(from), and the slider only shows later hours; label "Total from 4 PM"); switching product, model or run keeps the nearest valid time. Models: HRRR (3 km CONUS, hourly runs, 0–18 h, 0–48 h at 00/06/12/18Z), NAM 3 km nest (0–60 h hourly), NAM 12 km (`awphys`, 614×428 Lambert, hourly to 36 h then 3-hourly to 84 h; precip is 0–N then 12-h buckets on 00/12Z runs but 3-h buckets on 06/18Z runs), RAP (13 km, hourly runs to 21 h, 51 h at 03/09/15/21Z; NOAA's AWS bucket `noaa-rap-pds` sends no CORS header and its 13 km Lambert files are JPEG2000-packed, so it reads the native `wrfprs` files (NCEP rotated lat/lon grid, template 3.32769) from Google Cloud's public mirror `rapid-refresh` through the JSON API (`storage.googleapis.com/storage/v1/b/rapid-refresh/o/…?alt=media`, CORS-open with Range; listing as JSON with page tokens); decoded with 0 mismatches vs eccodes, corners round-trip exactly, 2-m temperatures within ~2 °F of HRRR at 7 cities; winds rotated by the grid-x-axis angle found numerically; offered for places north of 15°N and west of 50°W), GFS (0.25° global, 0–384 h every 6 h) and NBM (National Blend of Models, 2.5 km CONUS, hourly runs to 264 h: files hourly to 36 h, 3-hourly to 192, 6-hourly after; listings are paginated since NBM has 10 files per hour; products limited by `has()` and per-product hours by `okHour()`/`hrs`: total, 6-hr and 24-hr precip (1-h buckets to 48 h; 6-h buckets only end at 00/06/12/18Z, so past 48 h only synoptic-hour runs reach 11 days), snowfall with NBM's own snow-to-liquid ratios (ASNOW 1-h buckets, m, to 48 h), ice (FICEAC flat ice accumulation, kg/m² = mm, to 48 h), 2-m temperature, feels-like (APTMP), daytime highs (TMAX 12-h ending 00Z) and overnight lows (TMIN ending 12Z); checked against a direct eccodes sum: 24-h snow 10.276 in and precip 1.170 in at the same point), from NOAA Open Data on AWS (`noaa-hrrr-bdp-pds`, `noaa-nam-pds`, `noaa-gfs-bdp-pds`, `noaa-nbm-grib2-pds`: CORS-open with Range; ECMWF's open-data bucket answered "SlowDown" repeatedly, so it isn't used). Runs come from S3 listings per run prefix (default = newest run at least half published; the run menu lists the last few, partial ones as "(to N h)"); each field is one byte range from the file's `.idx`, taking only the plain entry (NBM lists probabilities/percentiles under the same name and time, e.g. "prob >0.254") (NAM packs U+V wind in one message, idx "N.1/N.2": the range ends at the next larger offset and `parse(b, sub)` picks the field; a 200 reply to a range request is cancelled, never read). Built-in GRIB2 decoder: templates 3.0 (lat/lon) and 3.30 (Lambert; grid-relative winds rotated by n·(λ−λ0) for barbs), packing 5.0/5.2/5.3 (complex + spatial differencing, missing-value management) and bitmaps; scanning-mode bit 0x10 (NBM: alternate rows run backwards) is flipped back — eccodes leaves those rows in file order, so its value comparison can't catch that; verified value-for-value against eccodes on HRRR/NAM/GFS fields (0 mismatches; projection within ~1e-13°); ~30–200 ms per field. Two workers (same file, `INW` branch) fetch (range reads kept in the Cache API `wx-model-1`, pruned after 30 h), decode, compute the product and crop it to the view plus half a view on each side at a stride matching the screen (contour grid lightly 3×3-smoothed, barb u/v at 3× stride); frames re-crop when the view leaves that area or zooms in 0.8+. Products (`P` in the file; `only` limits models; window products `win`/`base` = total over the last 6 or 24 h, computed as total(h) − total(h − win), shown for periods ending from now on — the custom versions of the NWS 6-hour QPF/SnowAmt/IceAccum and WPC daily maps): precip type & reflectivity (REFC + CRAIN/CSNOW/CFRZR/CICEP), total precip, MSLP & precip type (isobars every 4 hPa, H/L), 10:1 snowfall (HRRR/NAM accumulated WEASD ×10; GFS 6-h APCP × CSNOW average ×10), HRRR variable-density snowfall (ASNOW), freezing rain (HRRR FRZR; others APCP × CFRZR), 2-m temperature (32 °F line), 2-m dew point, 850-mb temperature & height, 10-m wind (barbs), gusts, SBCAPE, 0–3 km SRH, updraft helicity (HRRR/NAM), 500-mb height & wind, 250-mb jet, PWAT, cloud cover. Run totals sum each model's buckets (`bucket(model, h, id)`: HRRR and GFS precip use the 0–N run total directly, NAM 3-h buckets, GFS 6-h for snow/ice, NBM precip 6-h buckets at multiples of 6 h and 1-h otherwise, NBM snow/ice 1-h), memoised per hour; whole-day accumulations appear as "0-1 day acc" in the idx (both forms tried). Drawing: its own canvas slippy map (base, field, map lines/labels from `wx-vmap.js`, overlay for contours/barbs/marker), CSS transform during gestures with a 20% margin, field sampled per CSS pixel (bilinear values, banded Pivotal-style colour LUTs), Local/Region/U.S. presets, tap for the value at a point, double-tap zoom, loop plays loaded hours (0.42 s per step, last holds 1.3 s); switching model or run keeps the nearest valid time. HRRR and NAM are disabled outside CONUS (falls back to GFS). `WXVMap.init` keeps lists of ready/tile callbacks so the radar and the maps share it. A field is ~0.5–2 MB per hour (NAM largest), so only the shown hour ±2 load until Play. Under it, the "NWS maps" card keeps the original public-domain image products (NDFD 6-hr QPF/snow/ice, highs/lows, temperature/feels-like by time; WPC 1–7 day QPF, 4/8/12" snow and 0.25" ice odds, days 4–7 snow; CPC 6–14 day and week-2 outlooks) by URL, with `MCATS` in `app.js` and its own controls (`#iprev`/`#iplay`/`#irange`/`#inext`, full-screen viewer `#mfull`): the probabilistic WPC/CPC products have no browser-readable data (the NDFD bucket `noaa-ndfd-pds` sends no CORS header), so they stay as images. The Storm totals card (NWS official forecast) stays at the bottom.
- Radar tab: `wx-radar.js`, a dependency-free canvas slippy map (pan, pinch, double-tap, wheel; base/radar/label canvases). Radar first reads MRMS straight from NOAA Open Data on AWS (`noaa-mrms-pds`, CORS-open, ~2 min latency; `src: "s3"`) on whichever of NOAA's five grids holds the location (`DOMS`/`domFor`: CONUS, ALASKA, HAWAII 0.005°, CARIB, GUAM 0.005°; the worker gets the grid via a `dom` message; backups are CONUS-only, elsewhere a failure shows "Radar couldn't load right now"): S3 listings pick 11 `SeamlessHSR_00.00` scans (lowest clean scan; on Oct 1 it kept heavy cores the merged `MergedBaseReflectivityQC` product softened — Level II 40+ dBZ cores shown as 40+: 66% vs 0% south of Rochester, 93% vs 82% near KTLX — with the same bird filtering; decoded exactly, 0 mismatches) (newest + nearest to fixed 6-min marks, so refreshes only fetch new ones) and matching `PrecipFlag_00.00`; the workers (device cores − 1, 2–4) split the frames, gunzip with DecompressionStream, parse GRIB2 template 5.41 (value = (R + X·2^E)/10^D from a PNG-packed grid, decoded by a built-in streaming PNG reader), and keep a 0.01° 1600×1600 box around the view (`needBox`, re-decoded from the kept file when you move ~4.5°+) plus a 0.04° CONUS copy averaged in linear Z (max-pooling made rain areas ~15% too large and doubled 40+ dBZ core area when zoomed out); the newest scan borrows the latest PrecipFlag up to 10 min older (NOAA posts it a couple of minutes after the reflectivity); snow shows from 5 dBZ where PrecipFlag says snow, rain from 10; echoes under 20 dBZ are shown only where PrecipFlag says precipitation (checked against 15 radars' dual-pol scans: removed most leftover bird/insect and blocked-beam echoes, e.g. KFTG radar-confirmed share 70→89%, KBRO 49→82%, while losing ≤2% of real weather echoes); tiles are drawn from those exact values (bilinear, type nearest; up to tile zoom 10). Verified cell-for-cell against eccodes (0 mismatches, fine and averaged grids). Oct 1 validation (live data, 8 places): drawn values within ~0.6–0.9 dBZ of the grid (−0.3 colour-rounding bias), echo coverage within 1–3% (edges), type 98–100%; against Level II dual-pol, 97–100% of weather echoes (CC≥0.95) shown, 100% of 40+ dBZ cores, and 0–2.4% of bird/insect echoes (CC<0.8) — e.g. 0 of 237k at KMPX. ~16 MB on first open; each worker decodes its frames one after another, newest first, while its downloads run ahead in their own chain; on a first load every worker gets its list at once (so tile requests wait for their frame; a tile requested before its worker knew the frame used to fail for good and left every other frame blank, pulsing the loop) but the others hold their downloads (`hold`, then `go`) until the newest scan lands or 4 s pass; downloaded files are kept in the Cache API (`wx-mrms-1`, file names never change, pruned after 2 h) so reopening fetches only new scans (25 Mbps test: first open is bandwidth-bound at ~16.6 MB, newest ~1.2 s, all ~5.4 s; reopen ~3.9 s with nothing downloaded). Per scan, decode is ~0.4 s on desktop, mostly native inflate of the 49 MB grid; cells without echo skip the linear-Z sum (identical output). Refresh follows the data (`plan()`): NOAA scans every 2 min and posts each ~1 min after its valid time (PrecipFlag ~1.5 min), so the listing is re-checked at newest scan + 2 min + 62 s (and + 105 s for the newest scan's own PrecipFlag, which then replaces the borrowed one: the worker re-fetches it and the tile key includes the flag time), then every 15 s until it appears (60 s if the feed is 10+ min behind) and right away when the page becomes visible; new scans show ~65 s after valid time (other sources every 5 min). Time block at the right of the play bar (`.rtime`, RadarScope's product time): the shown scan's time, "Updated h:mm" under it (last check that succeeded, or when new scans finished loading; spinner while checking), both red (`.late`, `--crit`) when the newest scan is over 8 min old (16 for backups); tapping it jumps to the newest scan and checks for a new one now; a 15 s ticker keeps it current. The line under the map (`#rnow`, `nowLine()`) is normally empty; it only appears when the newest scan is over 15 min old or the unfiltered backup is on (no product names). The source and any failure reason are in `WXRadar._state()` (`src`, `why`, `dom`) and in check.html. Known limitation: MRMS Hawaii drops some shallow showers the Molokai radar sees (~70% of its weather echoes shown on Oct 1). If that fails it tries NOAA MRMS from NCEP's GeoServer (`opengeo.ncep.noaa.gov/geoserver/conus/`: `conus_bref_qcd` reflectivity + `conus_pcpn_typ` precip type, WMS tiles in EPSG:3857, 11 frames ~6 min apart over the last hour from the capabilities' time list); pixels are decoded back to exact values with the layers' JSON legends and drawn by type (rain on NWS/RadarScope breakpoints: greens to 34 dBZ, yellow 35, orange 45, red 50, dark red 55, magenta 60, snow white→blue, hail magenta cores). If NCEP isn't reachable with CORS it falls back to NOAA's quality-controlled MRMS SeamlessHSR as served by IEM (`src: "iemq"`: latest time from `/data/gis/images/4326/mrms/lcref.json`, tiles `cache/tile.py/1.0.0/mrms::lcref-YYYYMMDDHHMI/{z}/{x}/{y}.png`, 11 frames 6 min apart, decoded with IEM's gr2ae table `LCP`, index i = −32 + i/2 dBZ; no type). MRMS products remove birds, insects and clutter — on an Oct 1 night the raw KARX/KMPX scans showed 20–30 dBZ migration echoes over Rochester (CC 0.5–0.8) that MRMS correctly left out. Only if those tiles don't load does it fall back to the unfiltered IEM NEXRAD N0Q mosaic (`nexrad-n0q-900913[-mNNm]`, decoded with IEM's exact 255-colour N0Q table `IEMP` — index i = −32 + (i−1)/2 dBZ — rain palette, no type). Recoloured style = decode to dBZ, 2× bilinear resample, then colour (no blur: it shaved storm cores in a Level II comparison); tap the legend for the source's own colours (the legend is just the Rain/Snow colour bars with no "light → heavy" caption; backups add "Tap for NWS colours"; the Snow row only shows with MRMS). A tile that isn't loaded yet is drawn from its loaded children (two levels down, so zooming out never goes blank), else from a loaded ancestor (radar `drawKids`, vector `kids`); preload requests the frames on screen first. Tile fetch/decode/smoothing and the storm-motion match run in two background workers (the same `wx-radar.js` file, `INW` branch; needs OffscreenCanvas 2D) and fall back to main-thread ~10 ms slices; `wx-vmap.js` likewise decodes vector tiles in a worker. Each layer (base `RV.B`, radar `RV.R`, lines/labels `RV.L`) keeps its own drawn view and CSS transform; mid-gesture a layer is redrawn once 65% of its 20% margin is used, at most one stale layer per frame (radar follows the view every frame while playing); tile arrivals mid-gesture mark layers dirty at most every 180 ms. The radar canvas renders at 1.5× (base 2×, labels 3×). Playback glides continuously (0.55 s per step, latest frame holds 1.6 s): each pair of frames gets a storm-motion vector from a coarse-to-fine block match (1/6-scale alpha grids, search range sized for storms up to 160 km/h at the current zoom, sub-cell parabola fit, cached per area/zoom in world units); once all pairs are measured, unmeasurable pairs take their neighbours' motion and the vectors get a median-of-3 plus 1-2-1 pass (`settle`) so the glide keeps a steady pace; step durations follow the real time between scans, and the in-between draws frame A shifted forward and frame B shifted back along it while crossfading. Panning/zooming moves the canvas stage with a CSS transform (full display refresh rate); canvases are redrawn at gesture end or when the 20% margin runs out. Base map: `wx-vmap.js` decodes OpenFreeMap vector tiles (OpenMapTiles schema, no key; protobuf/MVT decoder built in; tile zoom = view zoom up to 7 (OpenMapTiles only carries county lines and trunk roads from tile z7, primary z8, secondary z9), view zoom − 1 above that; road visibility is left to the tile data except minor streets; points within 3/4096 of the last kept one are dropped at decode) and draws land/water under the radar (pure black land in dark mode for OLED) and county/state/country lines, roads and collision-checked place labels over it; the label canvas runs at up to 3× for sharp text. If the vector tiles can't be reached it falls back to Esri Canvas raster tiles. Locate button (`.rloc`): flies to the device's actual GPS position (browser geolocation `watchPosition`, not the forecast location) and stays locked on it as it updates; while locked it is replaced by a pin button (`.rhome`) that flies back to the forecast location; dragging or pinching unlocks (both buttons show). Markers: blue dot = device (or the forecast location while `wx-follow` is on, passed as `opts.mine`), neutral ring = any other forecast location. `check.html` reports the radar source and colour mode.
- Hourly cards, top to bottom: Precipitation (chance line on a 0–100% scale with the NWS wording bands, hourly bars coloured by type and split when types mix, thunder/hail/fog marks along the top, amount boxes per NWS block for rain (labelled "Liquid" when snow or ice is also forecast)/snow/ice), Temperature, Wind, Cloud Cover.
- While the current observation shows precipitation (rain, snow, sleet, freezing rain, hail, thunder; not "in Vicinity") or the hourly forecast has a 50%+ chance of it in the current hour or the next two (`precipSoon`), the Now tab shows the same Precipitation card between the conditions and today/tonight (`renderGraph(el, "precip")`, hold-to-read wired by `wireScrub`). The Hourly graphs and this card are separate instances (`G` and `GN`); keep selectors scoped to `#gin` or `#nowprecip`. Test scenarios start with their storm already underway so this card shows.
- Hourly graphs share one native horizontal scroller (`.gall`) so sideways scrolling runs at the display's full refresh rate; card boxes are drawn behind it (`.gbg`, sized by `gLayout()`), and titles, legends and y-axes stay put with `position:sticky`. Don't give cards their own scrollers or sync scroll positions in script.
- `wx-live.js` fetches live data in the browser on every open/refresh: api.weather.gov (points, forecast, gridpoint data, alerts, observations, AFD/HWO products), forecast.weather.gov MapClick JSON (for the site's exact period wording and precip-trend percentages), EPA Envirofacts UV (daily + hourly), and the ArcGIS World Geocoder for location search. All allow cross-origin requests.
- `wx-normalize.js` turns those responses into the one data document `app.js` renders. Change data shape there, not in `app.js`.
- Start tab: reopening within 30 min of the last visit returns to the tab you were on (`wx-tab`, `wx-tab-at` in localStorage; a `#tab` in the URL wins); after longer it starts on Now, and an installed app resumed after 30 min+ switches to Now.
- Location: `?q=City ST` or `?lat=..&lon=..` in the URL, else the last location used on the device (localStorage), else Minneapolis, MN. The location sheet offers "Use my current location" (browser geolocation, named via weather.gov points) and starred favorites (`wx-favs` in localStorage). Choosing current location turns on following (`wx-follow`, arrow before the place name): each later open, and returning after 10+ min, quietly re-checks position (skipped if permission is denied) and switches when it moved ~2 km+; picking any other place turns it off; a place in the URL is shown for that visit without turning it off, and the URL stays clean while following.
- Test scenarios: `wx-scenarios.js` builds sample weather (blizzard, ice storm, heat wave, severe storms, arctic cold) as api.weather.gov-shaped responses and runs them through `wx-normalize.js`. Open with `?test=blizzard` (etc.) or Location → Test scenarios; a banner shows while active and nothing is cached. Model maps stay live. Use them to check winter/severe layouts in any season.
- Live data check: `check.html` (Location sheet → Test scenarios → Run live data check) runs the real data pipeline for 13 places (incl. Alaska, Hawaii, Puerto Rico, Guam), audits the results, opens every tab in a hidden frame (`?nostore=1` so nothing is saved; the Maps tab must draw its first model frame) and decodes every model-map product × model once (`WXModels._probe`, values checked against plausible ranges) and sweeps the NWS map images (first/last frame, local and US); "Copy report" gives a text report. `?mock=1` runs it against the test scenarios without the network. The full run (and the "Radar accuracy only" button) also compares radar with station reports: latest weather.gov observation at ~49 airports (40 CONUS, AK, HI, PR, Guam) vs the radar value at the station as the map draws it (`WXRadar._probe`, max within ~5 km, frame nearest the observation): ✗ precipitation reported but no echo, ~ only very light echo, ! strong echo within ~5 km of a dry station, ↓ radar under ~25 dBZ for a moderate or ~35 dBZ for a heavy rain report.
- Deep radar audit (not part of the site): `python tools/radar_audit.py [RADARS…]` compares what the map draws with each NEXRAD's Level II scan (what RadarScope shows) for the radars with the most precipitation now, and exits 1 if all-radar bias is outside ±1.5 dB, heavy 35+ area is under 80% of Level II's, under 85% of 40+ cores show as 35+, or more than 5% of bird-only cells show. Oct 1 2026 baseline (22 radars, SeamlessHSR): bias −0.1 dB, 35+ area 14.3% vs 15.1%, 40+ area 5.9% vs 6.3%, cores ≥35 91%, birds 1.5% (merged base product had been −1.8 dB, 10.4% vs 15.1%, 84%, 4.0%). Run it after any change to radar sources, colours or display rules. Run it before publishing changes that touch data, maps or rendering, and after NWS changes.
- Self-update: `checkVersion()` in `app.js` fetches index.html (no-store) when the page becomes visible, on the refresh button and every 10 min, and reloads if its `app.js?v=` number is higher than the running one — so always bump `?v=` in index.html when publishing.
- `sw.js` only retires the old Sky Report service worker; don't add caching back without a cache-busting plan.

## Checks before publishing

- No runtime JavaScript errors; layouts work at 360–430px wide in light and dark mode.
- Load Minneapolis, run a location search, and open each tab against live data.
- Keep it dependency-free and static-host compatible.
