# Repository workflow

Tyler's personal GitHub Pages weather site: a single-page, live weather.gov dashboard.
Optimize for a simple loop: request, implement, review, publish, verify.

## Publishing

- Work directly on `main` unless Tyler asks for a branch or pull request.
- Start with `git status`; when clean, `git pull --ff-only origin main`. Never discard pre-existing changes.
- Commit task-scoped files with a descriptive message and push with `git push origin main` without waiting for approval. Never force-push.
- After pushing, confirm `origin/main` has the commit and the GitHub Pages build finished, then load the live site and confirm it serves the change.
- End every reply that involves a change with:

  ```
  ---
  - **Done:** what changed (and the commit/deploy status)
  - **Couldn't do:** anything skipped, unverified, or blocked (or "Nothing")
  - **Your action items:** what Tyler needs to check or decide (or "None")
  ```

## How the site works

- `index.html` holds the markup and all CSS; `app.js` renders everything (Now, Daily, Hourly graphs, Maps with storm totals, Observations, location picker, refresh button).
- Maps shows public-domain NWS/NOAA images by URL (no API): graphical.weather.gov NDFD sector PNGs (`images/{office|conus}/{Element}{N}_{sector}.png` for SnowAmt, IceAccum, QPF, MaxT, MinT, T, ApparentT, local = the location's forecast office), WPC winter/QPF GIFs, and CPC outlooks. Add products in `MCATS` in `app.js`.
- Radar tab: `wx-radar.js`, a dependency-free canvas slippy map (pan, pinch, double-tap, wheel; base/radar/label canvases). Radar first reads MRMS straight from NOAA Open Data on AWS (`noaa-mrms-pds`, CORS-open, ~2 min latency; `src: "s3"`) on whichever of NOAA's five grids holds the location (`DOMS`/`domFor`: CONUS, ALASKA, HAWAII 0.005°, CARIB, GUAM 0.005°; the worker gets the grid via a `dom` message; backups are CONUS-only, elsewhere a failure shows "Radar couldn't load right now"): S3 listings pick 11 `SeamlessHSR_00.00` scans (lowest clean scan; on Oct 1 it kept heavy cores the merged `MergedBaseReflectivityQC` product softened — Level II 40+ dBZ cores shown as 40+: 66% vs 0% south of Rochester, 93% vs 82% near KTLX — with the same bird filtering; decoded exactly, 0 mismatches) (newest + nearest to fixed 6-min marks, so refreshes only fetch new ones) and matching `PrecipFlag_00.00`; the workers (device cores − 1, 2–4) split the frames, gunzip with DecompressionStream, parse GRIB2 template 5.41 (value = (R + X·2^E)/10^D from a PNG-packed grid, decoded by a built-in streaming PNG reader), and keep a 0.01° 1600×1600 box around the view (`needBox`, re-decoded from the kept file when you move ~4.5°+) plus a 0.04° CONUS copy averaged in linear Z (max-pooling made rain areas ~15% too large and doubled 40+ dBZ core area when zoomed out); the newest scan borrows the latest PrecipFlag up to 10 min older (NOAA posts it a couple of minutes after the reflectivity); snow shows from 5 dBZ where PrecipFlag says snow, rain from 10; echoes under 20 dBZ are shown only where PrecipFlag says precipitation (checked against 15 radars' dual-pol scans: removed most leftover bird/insect and blocked-beam echoes, e.g. KFTG radar-confirmed share 70→89%, KBRO 49→82%, while losing ≤2% of real weather echoes); tiles are drawn from those exact values (bilinear, type nearest; up to tile zoom 10). Verified cell-for-cell against eccodes (0 mismatches, fine and averaged grids). Oct 1 validation (live data, 8 places): drawn values within ~0.6–0.9 dBZ of the grid (−0.3 colour-rounding bias), echo coverage within 1–3% (edges), type 98–100%; against Level II dual-pol, 97–100% of weather echoes (CC≥0.95) shown, 100% of 40+ dBZ cores, and 0–2.4% of bird/insect echoes (CC<0.8) — e.g. 0 of 237k at KMPX. ~16 MB on first open; each worker decodes its frames one after another, newest first, while its downloads run ahead in their own chain; on a first load the newest scan downloads alone (others start when it lands, or after 4 s); downloaded files are kept in the Cache API (`wx-mrms-1`, file names never change, pruned after 2 h) so reopening fetches only new scans (LTE-throttled test: all frames 5.7 → 3.3 s, newest 1.1 → 0.4 s; reopen 16 MB → 2.5 MB). Per scan, decode is ~0.4 s on desktop, mostly native inflate of the 49 MB grid; cells without echo skip the linear-Z sum (identical output). Refresh follows the data (`plan()`): NOAA scans every 2 min and posts each ~1 min after its valid time (PrecipFlag ~1.5 min), so the listing is re-checked at newest scan + 2 min + 62 s (and + 105 s for the newest scan's own PrecipFlag, which then replaces the borrowed one: the worker re-fetches it and the tile key includes the flag time), then every 15 s until it appears (60 s if the feed is 10+ min behind) and right away when the page becomes visible; new scans show ~65 s after valid time (other sources every 5 min). Time block at the right of the play bar (`.rtime`, RadarScope's product time): the shown scan's time, "Updated h:mm" under it (last check that succeeded, or when new scans finished loading; spinner while checking), both red (`.late`, `--crit`) when the newest scan is over 8 min old (16 for backups); tapping it jumps to the newest scan and checks for a new one now; a 15 s ticker keeps it current. The line under the map (`#rnow`, `nowLine()`) is normally empty; it only appears when the newest scan is over 15 min old or the unfiltered backup is on (no product names). The source and any failure reason are in `WXRadar._state()` (`src`, `why`, `dom`) and in check.html. Known limitation: MRMS Hawaii drops some shallow showers the Molokai radar sees (~70% of its weather echoes shown on Oct 1). If that fails it tries NOAA MRMS from NCEP's GeoServer (`opengeo.ncep.noaa.gov/geoserver/conus/`: `conus_bref_qcd` reflectivity + `conus_pcpn_typ` precip type, WMS tiles in EPSG:3857, 11 frames ~6 min apart over the last hour from the capabilities' time list); pixels are decoded back to exact values with the layers' JSON legends and drawn by type (rain on NWS/RadarScope breakpoints: greens to 34 dBZ, yellow 35, orange 45, red 50, dark red 55, magenta 60, snow white→blue, hail magenta cores). If NCEP isn't reachable with CORS it falls back to NOAA's quality-controlled MRMS SeamlessHSR as served by IEM (`src: "iemq"`: latest time from `/data/gis/images/4326/mrms/lcref.json`, tiles `cache/tile.py/1.0.0/mrms::lcref-YYYYMMDDHHMI/{z}/{x}/{y}.png`, 11 frames 6 min apart, decoded with IEM's gr2ae table `LCP`, index i = −32 + i/2 dBZ; no type). MRMS products remove birds, insects and clutter — on an Oct 1 night the raw KARX/KMPX scans showed 20–30 dBZ migration echoes over Rochester (CC 0.5–0.8) that MRMS correctly left out. Only if those tiles don't load does it fall back to the unfiltered IEM NEXRAD N0Q mosaic (`nexrad-n0q-900913[-mNNm]`, decoded with IEM's exact 255-colour N0Q table `IEMP` — index i = −32 + (i−1)/2 dBZ — rain palette, no type). Recoloured style = decode to dBZ, 2× bilinear resample, then colour (no blur: it shaved storm cores in a Level II comparison); tap the legend for the source's own colours (legend reads "Light → heavy" for both sources; the Snow row only shows with MRMS). A tile that isn't loaded yet is drawn from its loaded children (two levels down, so zooming out never goes blank), else from a loaded ancestor (radar `drawKids`, vector `kids`); preload requests the frames on screen first. Tile fetch/decode/smoothing and the storm-motion match run in two background workers (the same `wx-radar.js` file, `INW` branch; needs OffscreenCanvas 2D) and fall back to main-thread ~10 ms slices; `wx-vmap.js` likewise decodes vector tiles in a worker. Each layer (base `RV.B`, radar `RV.R`, lines/labels `RV.L`) keeps its own drawn view and CSS transform; mid-gesture a layer is redrawn once 65% of its 20% margin is used, at most one stale layer per frame (radar follows the view every frame while playing); tile arrivals mid-gesture mark layers dirty at most every 180 ms. The radar canvas renders at 1.5× (base 2×, labels 3×). Playback glides continuously (0.55 s per step, latest frame holds 1.6 s): each pair of frames gets a storm-motion vector from a coarse-to-fine block match (1/6-scale alpha grids, search range sized for storms up to 160 km/h at the current zoom, sub-cell parabola fit, cached per area/zoom in world units); once all pairs are measured, unmeasurable pairs take their neighbours' motion and the vectors get a median-of-3 plus 1-2-1 pass (`settle`) so the glide keeps a steady pace; step durations follow the real time between scans, and the in-between draws frame A shifted forward and frame B shifted back along it while crossfading. Panning/zooming moves the canvas stage with a CSS transform (full display refresh rate); canvases are redrawn at gesture end or when the 20% margin runs out. Base map: `wx-vmap.js` decodes OpenFreeMap vector tiles (OpenMapTiles schema, no key; protobuf/MVT decoder built in; tile zoom = view zoom up to 7 (OpenMapTiles only carries county lines and trunk roads from tile z7, primary z8, secondary z9), view zoom − 1 above that; road visibility is left to the tile data except minor streets; points within 3/4096 of the last kept one are dropped at decode) and draws land/water under the radar (pure black land in dark mode for OLED) and county/state/country lines, roads and collision-checked place labels over it; the label canvas runs at up to 3× for sharp text. If the vector tiles can't be reached it falls back to Esri Canvas raster tiles. Locate button (`.rloc`): flies to the device's actual GPS position (browser geolocation `watchPosition`, not the forecast location) and stays locked on it as it updates; while locked it is replaced by a pin button (`.rhome`) that flies back to the forecast location; dragging or pinching unlocks (both buttons show). Markers: blue dot = device (or the forecast location while `wx-follow` is on, passed as `opts.mine`), neutral ring = any other forecast location. `check.html` reports the radar source and colour mode.
- Hourly cards, top to bottom: Precipitation (chance line on a 0–100% scale with the NWS wording bands, hourly bars coloured by type and split when types mix, thunder/hail/fog marks along the top, amount boxes per NWS block for rain (labelled "Liquid" when snow or ice is also forecast)/snow/ice), Temperature, Wind, Cloud Cover.
- While the current observation shows precipitation (rain, snow, sleet, freezing rain, hail, thunder; not "in Vicinity") or the hourly forecast has a 50%+ chance of it in the current hour or the next two (`precipSoon`), the Now tab shows the same Precipitation card between the conditions and today/tonight (`renderGraph(el, "precip")`, hold-to-read wired by `wireScrub`). The Hourly graphs and this card are separate instances (`G` and `GN`); keep selectors scoped to `#gin` or `#nowprecip`. Test scenarios start with their storm already underway so this card shows.
- Hourly graphs share one native horizontal scroller (`.gall`) so sideways scrolling runs at the display's full refresh rate; card boxes are drawn behind it (`.gbg`, sized by `gLayout()`), and titles, legends and y-axes stay put with `position:sticky`. Don't give cards their own scrollers or sync scroll positions in script.
- `wx-live.js` fetches live data in the browser on every open/refresh: api.weather.gov (points, forecast, gridpoint data, alerts, observations, AFD/HWO products), forecast.weather.gov MapClick JSON (for the site's exact period wording and precip-trend percentages), EPA Envirofacts UV (daily + hourly), and the ArcGIS World Geocoder for location search. All allow cross-origin requests.
- `wx-normalize.js` turns those responses into the one data document `app.js` renders. Change data shape there, not in `app.js`.
- Start tab: reopening within 30 min of the last visit returns to the tab you were on (`wx-tab`, `wx-tab-at` in localStorage; a `#tab` in the URL wins); after longer it starts on Now, and an installed app resumed after 30 min+ switches to Now.
- Location: `?q=City ST` or `?lat=..&lon=..` in the URL, else the last location used on the device (localStorage), else Minneapolis, MN. The location sheet offers "Use my current location" (browser geolocation, named via weather.gov points) and starred favorites (`wx-favs` in localStorage). Choosing current location turns on following (`wx-follow`, arrow before the place name): each later open, and returning after 10+ min, quietly re-checks position (skipped if permission is denied) and switches when it moved ~2 km+; picking any other place turns it off; a place in the URL is shown for that visit without turning it off, and the URL stays clean while following.
- Test scenarios: `wx-scenarios.js` builds sample weather (blizzard, ice storm, heat wave, severe storms, arctic cold) as api.weather.gov-shaped responses and runs them through `wx-normalize.js`. Open with `?test=blizzard` (etc.) or Location → Test scenarios; a banner shows while active and nothing is cached. Maps stay live. Use them to check winter/severe layouts in any season.
- Live data check: `check.html` (Location sheet → Test scenarios → Run live data check) runs the real data pipeline for 13 places (incl. Alaska, Hawaii, Puerto Rico, Guam), audits the results, opens every tab in a hidden frame (`?nostore=1` so nothing is saved) and sweeps every Maps product for dead images; "Copy report" gives a text report. `?mock=1` runs it against the test scenarios without the network. The full run (and the "Radar accuracy only" button) also compares radar with station reports: latest weather.gov observation at ~49 airports (40 CONUS, AK, HI, PR, Guam) vs the radar value at the station as the map draws it (`WXRadar._probe`, max within ~5 km, frame nearest the observation): ✗ precipitation reported but no echo, ~ only very light echo, ! strong echo within ~5 km of a dry station, ↓ radar under ~25 dBZ for a moderate or ~35 dBZ for a heavy rain report.
- Deep radar audit (not part of the site): `python tools/radar_audit.py [RADARS…]` compares what the map draws with each NEXRAD's Level II scan (what RadarScope shows) for the radars with the most precipitation now, and exits 1 if all-radar bias is outside ±1.5 dB, heavy 35+ area is under 80% of Level II's, under 85% of 40+ cores show as 35+, or more than 5% of bird-only cells show. Oct 1 2026 baseline (22 radars, SeamlessHSR): bias −0.1 dB, 35+ area 14.3% vs 15.1%, 40+ area 5.9% vs 6.3%, cores ≥35 91%, birds 1.5% (merged base product had been −1.8 dB, 10.4% vs 15.1%, 84%, 4.0%). Run it after any change to radar sources, colours or display rules. Run it before publishing changes that touch data, maps or rendering, and after NWS changes.
- Self-update: `checkVersion()` in `app.js` fetches index.html (no-store) when the page becomes visible, on the refresh button and every 10 min, and reloads if its `app.js?v=` number is higher than the running one — so always bump `?v=` in index.html when publishing.
- `sw.js` only retires the old Sky Report service worker; don't add caching back without a cache-busting plan.

## Checks before publishing

- No runtime JavaScript errors; layouts work at 360–430px wide in light and dark mode.
- Load Minneapolis, run a location search, and open each tab against live data.
- Keep it dependency-free and static-host compatible.
